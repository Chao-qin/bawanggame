# 模拟器启动遮挡与横屏键组设计

## 目标行为

修复 J2ME/MRP 模拟器首帧加载时编辑桥接节点按浏览器默认样式绘制白框的问题，并把没有保存过自定义布局的横屏模拟器默认调整为“导航键组左、数字键组右”。

## 修改范围

- React 手机壳在首次绘制前通过 inline style 为编辑桥接层提供隔离状态，避免样式异步加载期间产生可见输入控件；J2ME 等待运行时 CSS 完成后再加载脚本，由 `lcdui.js` 接管时清除这组初始 style。
- 保留 J2ME 的六个原生编辑桥接节点；运行时请求文本输入时，现有 `setVisible(true)` 和 `.textEditor.show` 继续负责显示、聚焦和接收输入。
- 将触摸布局默认值的横屏两侧设为 `swapped`，并保持已写入 `localStorage` 的布局设置优先。
- 删除横屏布局中的重复规则，保证导航键组和数字键组按固定网格列布局，不被旧的全宽规则拉伸。
- 同一个交付分支和 PR 包含 spec、plan、代码和验证记录，不提交构建生成物。

## 不可破坏的现有行为

- J2ME 文本输入、输入法聚焦、编辑器尺寸/位置和键盘事件映射保持不变。
- MRP 的 `#mrp-dialog-text` 仍可见并可编辑；MRP 专用编辑层继续移出视口。
- 用户已有的 `touchLayout.sides`、D-pad 方向、数字键顺序和动作映射继续生效。
- 竖屏、自动方向、全屏、设置面板和游戏退出流程不改变。

## 验收标准

1. 模拟器 React 节点第一次绘制时，六个编辑桥接节点不在视口内，也不产生白色输入框或布局占位。
2. J2ME 游戏实际打开文本输入时，编辑器仍能显示、聚焦、输入并回写运行时。
3. MRP 启动和游戏画面不出现白色编辑框，MRP 文本对话框仍可输入。
4. 新用户进入横屏时，导航键组在左侧、数字键组在右侧；已有保存布局的用户保持原选择。
5. `pnpm --filter @xiaochao/web build` 成功，`git diff --check` 无错误，并完成桌面浏览器启动层面的冒烟验证。

## 验证边界

本次没有真实 Android/iOS 设备，因此记录桌面 Chromium 和现有 Node 构建验证结果；真机输入法、设备旋转和 WebView 首帧合成仍属于残余风险。
