# J2ME 循环抢占：修复整页卡死

## 1. 目标

| 项 | 内容 |
|---|---|
| 目标行为 | J2ME 游戏执行不让出的循环（忙等、无 sleep 的主循环）时，页面仍能响应，其他 Java 线程和浏览器事件照常运行 |
| 修改范围 | `runtime/j2me/bld/j2me.js` 的让出分析（`canYield`）和基线编译器（`emitBlockBody`）；`RUNTIME_VERSION` 升到 `20261127-1` |
| 不可破坏 | 现有游戏的帧率和主线程占用不下降；不会让出的方法仍不生成展开代码 |
| 验收 | 最小复现 MIDlet 在修复前整页冻结、修复后持续响应并能结束循环；三款真实游戏修复前后帧率在误差范围内 |

## 2. 原因

J2ME 虚拟机和页面共用一个主线程。每个执行窗口（16ms）结束时，正在运行的 Java 线程要靠抢占检查把主线程交还给浏览器。修复前有两个漏洞：

1. **小循环不检查抢占。** 只有「可能让出」的方法才会在回跳时检查抢占。不超过 100 字节、也不调用会让出方法的循环（例如 `while (!ready) {}`）被判为不会让出，于是永远不会交出主线程。负责把 `ready` 置为真的线程得不到运行机会，循环永不结束。
2. **编译后的循环不检查抢占。** 解释器在每次回跳时检查抢占，但循环跑热后方法会被编译（或通过 OSR 切到编译代码），编译代码只在方法入口检查一次。之后，热循环只要不调用会让出的方法，就会一直占住主线程，大方法也一样。

两种情况都会让页面完全无响应，父页面同样冻结（同源 iframe 共用主线程），只能强制关闭浏览器。

## 3. 修改

| 位置 | 修改 |
|---|---|
| `canYield` | 字节码中出现回跳（`if*`、`goto`、`goto_w` 的目标不晚于自身）时返回 `Likely`。调用方据此生成展开代码，方法自身获得抢占检查 |
| `emitBlockBody` | 对可让出方法，在每个回跳目标（循环头）的块开头加抢占检查。被抢占时从该块起始处展开，解释器从这里继续执行 |
| `emitEntryPoints` | 方法入口的抢占检查按运行时 `pc` 展开。原来固定写 0：经 OSR 从循环头进入后被抢占，会从方法开头重跑循环前的代码，而局部变量已被循环改过。该问题原本就有，循环方法变为可让出后会更常走到 |

抢占检查由计数器采样（每 256 次才看一次时间），循环里的额外开销是一次自增和一次位与。

## 4. 验证

| 验证 | 结果 |
|---|---|
| `runtime/j2me/preemption.test.mjs` | 小循环判为可让出；只有前向跳转的方法仍不可让出；编译代码的入口检查按运行时 `pc` 展开、循环头检查按循环头位置展开。用原 `j2me.js` 跑时第 1、3 条失败；只回退循环头检查或入口 `pc` 修改时第 3 条失败 |
| 最小复现（Chromium 145，无头） | 主线程 `while (!flag) {}`、另一线程 300ms 后置位。修复前 2s 起整页冻结，父页面 rAF 也不再执行；修复后 rAF 延迟 3–5ms，约 1.6s 打印 `SPIN-DONE` |
| 大方法对照 | 同一循环填充到 110 字节以上，只回退编译器修改时仍冻结，两处修改都需要 |
| 真实游戏（4 倍 CPU 降速，393×851 移动视口，每轮 15s） | 修复前 → 修复后的游戏 fps：仙剑奇侠传 47.3/48.6/48.7 → 42.4/48.2/49.6；Diamond Rush 12.6/14.9/15.5 → 15.0/14.9/14.4；植物大战僵尸 14.7/14.9/14.9 → 14.7/14.8/14.9（第 3 轮为入口 `pc` 修正后）。页面 fps 与长任务数在误差范围内 |

## 5. 冒泡（MRP）卡顿

冒泡不在本次修改范围。测量结论（雷电 1944）：

| 页面 | 主线程长任务（8s 内） | 页面 fps |
|---|---|---|
| 本站冒泡播放器 | 5.2s | 39.2 |
| vmrp 原版 `main.html` | 4.6s | 41.4 |

约 65% 的主线程时间在 vmrp 游戏定时器回调里，即 unicorn 在 WebAssembly 中解释执行 ARM 指令。本站集成与原版开销相近，卡顿来自模拟器内核。4 倍降速（接近中端手机）时只有约 5fps。改善需要重新编译 vmrp（优化级别、unicorn 构建方式），vmrp 不在本仓库内，另行评估。

## 6. 残余风险

- 未在真实 Android 设备和 APK WebView 上验证。
- 只覆盖 `if*`/`goto`/`goto_w` 回跳；用 `tableswitch`/`lookupswitch` 回跳构成的循环（混淆器可能生成）仍不检查抢占。
- 循环方法变为可让出后，调用方多出展开检查。三款游戏测不出差异，个别重度计算游戏仍可能有小幅变化。
