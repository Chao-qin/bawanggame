# 上报接收与飞书日志

## 任务契约

- 目标：继续在 PR #78 补齐使用事件和前端报错接收、后端日志、控制台输出与飞书同步。
- 范围：现有 analytics、运行时错误入口、Nest 日志模块、部署配置及使用说明。
- 保持：v1 使用事件协议、游戏交互与设备身份；飞书凭据只在服务端读取；不使用数据库。
- 验收：错误/统计/后端日志分类、错误隔离、重试恢复、CORS/请求边界、真实飞书回读、构建与冷启动审查。

## 方案

采用每个环境一份电子表格、三个工作表「使用统计」「前端报错」「后端日志」。相较每类一个文件，此方案减少配置并保留分类。环境由服务端 `LOG_ENV` 决定，不能由客户端覆盖。

`POST /collect` 接收现有 v1 envelope；新增 `client_error` 事件，`error` 包含 `kind`、`message`、`stack`、`url`、`line`、`column`、`context`。使用事件维持原字段。Web 默认同源 `/collect`，显式空地址关闭；APK 使用构建时配置的 HTTPS 地址。

前端复用队列，捕获全局异常、未处理 Promise、资源加载失败、路由渲染异常及已处理的游戏启动错误；同源运行时 iframe 转交父页，不另记打开事件。取消和正常退出不作为错误。上报链路自身失败不递归上报。

后端校验版本、事件类型、批次及正文大小；忽略客户端提供的环境。规范化并脱敏后打印控制台，先持久化到本地文件队列，再确认接收；后台批量追加飞书，失败保留重试，重启恢复。事件 ID 用于重试去重；飞书成功响应丢失仍可能产生重复行，表中保留事件 ID 供识别。

Nest 日志和 HTTP 异常进入同一模块；飞书同步失败直接输出到 stderr，避免日志递归。凭据、Authorization、Cookie、完整请求正文不进入日志。队列限额耗尽时拒绝新上报，客户端保留重试。

## 配置与边界

服务端读取 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_SPREADSHEET_TOKEN`、三个 `FEISHU_*_SHEET_ID`、`LOG_ENV`、`LOG_DIR`。配置说明和 Compose 负责注入，不修改 `.env*`。飞书未配置或不可用时，本地队列保留待同步。

本地日志目录需要可写且持久化；单个服务实例独占目录。此方案不依赖数据库或外部队列服务。日志用于诊断，不作为审计不可丢失保证；浏览器存储配额、设备清理和极端容量限制仍可能导致丢失。

真实飞书创建和回读需要指定应用的电子表格权限。未开通时先完成代码与模拟验证，不使用其他应用冒充成功。
