# 52java 商城与现代虚拟手机设计

## 目标

将 52java 作为小潮霸王的商城底座：在站内浏览可下载的 JAR，下载后直接进入本地 J2ME 库并启动；同时保留打开原站的入口。升级大厅和虚拟手机外壳，使其达到可长期使用的游戏平台界面，同时保持旧运行时 DOM id 和脚本协议兼容。

## 方案

- Node 服务通过 `52JAVA_BASE_URL` 配置连接 `https://java.52emu.cn`，从 PHP 目录页读取 `index.php?q=all&p=…`，从详情页读取下载选项。
- 服务端提供受控的 `/__52java/catalog`、`/__52java/download` 和 `/__52java/open` 接口，不把任意 URL 变成开放代理。
- 下载接口只接受数字游戏 id，按详情页提供的下载选项请求 `download.php`，仅允许跳转到站点及 `d2.52emu.cn` 文件域；校验 JAR ZIP 签名后写入 `games/jar`，冲突时生成不覆盖的文件名。
- React 增加商城导航、目录卡片、下载状态、刷新本地库和打开原站按钮；下载成功后自动刷新 J2ME 游戏列表。
- 大厅使用深色游戏平台布局，增加顶部导航、商城搜索/分类/分页和空态；虚拟手机增加设备状态层、运行工具条和响应式设备框架，底层运行时 id 保持不变。

## 数据流与错误处理

商城请求失败显示明确错误和重试按钮，并保留原站入口。下载期间按游戏 id 去重；失败恢复可重试。服务端拒绝非白名单来源、非法 id、非 JAR 内容和超过大小上限的响应。

## 验证

- `pnpm --filter @xiaochao/web build`、服务端 typecheck 和现有 smoke test。
- HTTP 验证商城目录、下载校验、JAR 列表和根页面。
- 启动开发服务，用实际浏览器检查商城 tab、下载反馈、响应式布局、虚拟手机工具条和 J2ME 启动路径。
