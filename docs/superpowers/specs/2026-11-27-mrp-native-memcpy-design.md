# 冒泡内核：原生执行系统层 memcpy

## 1. 目标

| 项 | 内容 |
|---|---|
| 目标行为 | 冒泡游戏在手机上明显更流畅，画面与原内核一致 |
| 修改范围 | 新增 `runtime/mrp/vmrp/`（补丁、构建脚本、编译产物、说明）；播放器改从该目录加载内核；`pack-site.sh`、移动端资源校验、Vite 开发代理、README 同步 |
| 不可破坏 | 游戏画面与原内核一致；`fs/`、`midi.js`、游戏目录与远程镜像加载方式不变；`cfunction.ext` 不匹配时行为与原内核相同 |
| 验收 | 4 倍 CPU 降速下游戏画面刷新率与页面帧率提升；多款游戏的画面对比无渲染差异 |

## 2. 先查上游参数

| 位置 | 结论 |
|---|---|
| 网页版 `main.html` | 只有 `title`、`f` 两个 URL 参数，没有性能相关选项 |
| `wasm/Makefile` | `-Os`。实测改成 `-O2`/`-O3` 没有变化：热点在预编译的 `libunicorn.a` 里，链接阶段优化不到 |
| 编译开关 | `DEBUG`、`MEM_DEBUG`、`NETWORK_SUPPORT` 网页版均未开启，没有可省的开销 |
| `libunicorn.a` | 来自 unicorn.js，TCI 解释器，内部辅助函数已内联，说明当初已开优化 |

## 3. 原因

带函数名的构建做 CPU 采样：主线程时间主要在 `tcg_qemu_tb_exec_arm`（TCI 解释执行）和单字节读写慢路径。用 `UC_HOOK_BLOCK` 插桩统计客户机指令分布：

| 游戏 | `cfunction.ext` 中 `memcpy` 内循环（0x94EA0）所占客户机指令 |
|---|---|
| 雷电 1944 | 97.9% |
| 野蛮女教师 | 89.8% |

`cfunction.ext`（vmrp 的系统层，ARM 代码）的 `memcpy` 逐字节复制，复制屏幕缓冲时每个字节要解释执行 4 条指令。

## 4. 修改

补丁在 `cfunction.ext` 加载后核对 0x94E94 处的 8 条指令。一致时，在入口挂单指令代码钩子：原生完成复制（重叠时按原逐字节前向复制的结果），经 `uc_mem_write` 写回（会让被覆盖区域的已翻译代码失效），再把 R2 清零，原代码经 `subs r2, r2, #1; bxcc lr` 立即返回。

钩子不写 PC：unicorn 1 每次停止模拟都会清空整个翻译缓存，写 PC 会触发停止。指令不一致、长度为 0、地址超出模拟内存时，钩子什么也不做，交回原代码执行。

构建：Emscripten 2.0.12（与 `libunicorn.a` 的 clang 12 一致），参数与上游 `wasm/Makefile` 相同，去掉只在 `DEBUG` 下使用的 `debug.c`。`build.sh` 从上游提交 `ffe01e9` 打补丁重编，产物与提交的文件逐字节一致；不打补丁时与上游发布版只差 5 字节。

## 5. 验证

环境：Intel Xeon E5-2699 v4 开发机，无头 Chromium 145，393×851 移动视口，CDP 4 倍 CPU 降速，每项 10s。游戏刷新率 = 画布 `putImageData` 次数/秒。

| 游戏 | 原内核 游戏刷新 / 页面 fps / P95 / 主线程忙碌 / >50ms 帧 / 长任务 | 新内核 |
|---|---|---|
| 雷电 1944 | 4.6 / 4.8 / 250ms / 96% / 43 / 45 | 8.9 / 54.9 / 33ms / 7% / 1 / 12 |
| 野蛮女教师 | 5.3 / 5.3 / 200ms / 97% / 50 / 52 | 8.8 / 45.2 / 50ms / 36% / 14 / 55 |
| gslcq | 5.5 / 21.2 / 133ms / 81% / 53 / 54 | 10.2 / 40.5 / 50ms / 64% / 17 / 101 |
| gzmb | 6.4 / 6.4 / 167ms / 97% / 62 / 64 | 14.1 / 14.1 / 83ms / 96% / 138 / 140 |
| ggfftb | 3.4 / 3.4 / 300ms / 96% / 32 / 34 | 8.7 / 45.7 / 50ms / 50% / 10 / 85 |
| gxxdd | 4.3 / 4.3 / 250ms / 96% / 41 / 43 | 12.9 / 14.1 / 83ms / 96% / 125 / 129 |
| gmhkz | 5.2 / 5.2 / 217ms / 96% / 49 / 51 | 8.8 / 8.8 / 133ms / 96% / 86 / 88 |
| axhzd | 测试期间画面静止，两者都为 0 刷新、60fps | 同左 |

不降速时，雷电 1944 和野蛮女教师的游戏刷新都是 9.6/s（游戏自身定时器上限），主线程忙碌从 62–63% 降到 0%。

画面对比：两个内核在同一时间点按同样的键，截取 6 个检查点的画布。gslcq、gzmb、gxxdd、axhzd、野蛮女教师全部逐像素一致；雷电 1944、ggfftb、gmhkz 的差异经截图核对为动画相位（闪烁文字、子弹、海面滚动），不是渲染错误。

加载核对：vendor 目录保持上游原版时，页面请求 `/runtime/mrp/vmrp/vmrp.js` 与 `vmrp.wasm`，`fs/` 与 `midi.js` 仍来自 `/maopao/vmrp_v1.0/`。

打包核对：`pnpm run pack` 后 `site-deploy/runtime/mrp/vmrp/` 含 `vmrp.js`、`vmrp.wasm`，`site-deploy/maopao/vmrp_v1.0/` 只含 `fs/`、`fs.js`、`midi.js`。`pnpm test:web` 115/115 通过。

## 6. 残余风险

- 未在真实 Android 设备和 APK WebView 上验证，未构建 APK（`verify-web-assets` 未实际运行）。
- gzmb、gxxdd、gmhkz 在 4 倍降速下主线程仍满载（游戏刷新已提升 1.7–3 倍），剩余热点未分析。
- 加速只在 `cfunction.ext` 与 vmrp.github.io 提交 `7f96c715` 中的版本一致时生效；换版本时自动退回原逐字节复制。
- 新内核下长任务数可能上升（游戏刷新更多、每次更短），卡顿以帧间隔 P95 为准
- 编译产物（约 2.1MB）入库：Emscripten 2.0.12 不在 CI 中，产物由 `build.sh` 复现。
